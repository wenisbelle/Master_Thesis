# Road to an A1 paper

A guideline for getting the thesis work ready for an A1 journal. It is based on a
comparison with Lamenza, Olivieri & Endler, *Deep Reinforcement Learning Approaches
for Sensor Data Collection by a Swarm of UAVs*, Advanced Intelligent Systems (2026),
doi:10.1002/aisy.202501146.

## Why that paper was accepted

Its system is simple: a global satellite link, no energy model, no outside baseline.
It was accepted because the evidence is clean:

- **One question, with a controlled comparison.** 4 variants, and each one changes one thing.
- **A few standard metrics**, measured the same way everywhere: success rate,
  completion time, training time.
- **A fixed experiment grid:** 3 agent counts × 3 sensor counts × 500 runs.
- **Small claims, each backed by a number and a figure.**
- **Honest failure analysis and limitations**, plus public code.

**Lesson:** reviewers accept a modest contribution when the evidence is clean.

## Our angle

The paper says its main limitation is the **global communication link**. Its future
work lists **energy handling and communication failures**. This work does
energy management and base congestion with **no central communication**, in the
same simulator (GrADyS-SIM NextGen). Cite the paper as the gap we fill, both in the
introduction and in the cover letter.

## The main claim (pick one and keep the paper around it)

> Decentralized, gossip-based energy coordination keeps coverage close to a
> centralized oracle across communication ranges, while avoiding base congestion.

Multiple bases, robustness and so on support this claim. They are not separate stories.

## Baseline ladder

Each level adds one thing, so each gap in the results has one cause.

| Level | Return rule | Adds | Proves | Status |
|---|---|---|---|---|
| Naive | battery < fixed % (e.g. 30%) | — | being energy-aware matters at all | to do (optional, cheap) |
| **Egocentric** | own battery, energy to base by distance, tuned `CHARGE_MARGIN`, `energy_effect` on the map | energy model | the energy model helps on its own | exists, **needs retuning** |
| **Swarm** | egocentric + swarm mean battery + congestion (genes a/b/c) | information from the other drones | **main claim** | exists |
| Oracle | centralized, full information, assigns base and time slots | perfect information | how much decentralization costs | to do (**important**) |

## To do, in order

### 1. Fair comparison (blocking: without it the paper is rejected)
- [ ] Retune egocentric for each transmission range on the current scenario, with the same
      GA budget, seeds and bases as swarm.
- [ ] Sanity-check every tuned individual before comparing: no drones die, it
      recharges, and coverage is reasonable. (The egocentric 200 m logbook individual
      never recharged and all its drones died.)
- [ ] Make the systems differ **only** in the energy logic (check `INITIAL_UNCERTAINTY`).

### 2. Show the GA actually tunes something
- [ ] Re-evaluate the best individual of each generation on a **fixed validation set**
      of seeds and bases.
- [ ] Plot validation cost against generation, with confidence intervals. The improvement must be clearly larger than
      the 3–5% noise between generations.
- [ ] Compare against a random or default individual, so "why use a GA?" has an answer.

### 3. Baselines
- [ ] Naive fixed-threshold baseline.
- [ ] Centralized oracle (upper bound).
- [ ] (If possible) one method from the literature on persistent coverage with recharging.

### 4. Standard metrics (on top of our uncertainty integral)
- [ ] Coverage over time, plus the mean and maximum time since each cell was last visited (age of information).
- [ ] Dead drones (count, and how many runs have any death at all).
- [ ] Charging congestion: time over capacity Nc, and the maximum excess.
- [ ] Number of drones mapping over time.
- [ ] Communication overhead: messages and bytes per drone per second.

### 5. Experiment grid and statistics
- [ ] Fixed grid: transmission range × number of drones (3/5/7/10) × number of bases.
- [ ] Many seeds per cell (≥ 30) with fixed seed lists, saved in the repo.
- [ ] Report mean ± 95% confidence interval, and use a paired test (e.g. Wilcoxon) between systems on the
      same seeds.
- [ ] Congestion: test against a **random-arrival null model** to show the
      coordination is real.
- [ ] The central figure is each metric against transmission range, one line per system, with the oracle as a
      reference line.

### 6. Robustness (strong extra)
- [ ] Packet loss in the gossip.
- [ ] A drone failing in the middle of a run (the paper's Fig. 3b failure mode: agents keep
      trusting a teammate that has failed).
- [ ] A base becoming unavailable (multi-base scenario).

### 7. Writing
- [ ] Introduction: the gap is energy plus no central communication. Cite the paper's limitations.
- [ ] Related work: one sentence for each group of papers on how we differ.
- [ ] Failure analysis section: show and explain the bad runs.
- [ ] Limitations section.
- [ ] Public code with a tagged release, plus the exact commands that regenerate every figure.
- [ ] Plots readable without colour: Okabe-Ito palette plus line styles and markers.
- [ ] Check the target journal's Qualis rating **in our CAPES area**.

## Pitfalls to remember
- Adding any node (e.g. a base) changes the event order in gradysim, so runs are not
  reproducible bit-for-bit across scenarios. Compare **statistically over seeds**.
- A new scenario every GA generation makes the logbook minimum noisy. Always validate on fixed seeds.
- Never compare against a baseline that was not tuned on the same scenario.
